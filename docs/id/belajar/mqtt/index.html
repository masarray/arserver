Dasar MQTT

MQTT mengubah nilai relay terpilih menjadi data yang bisa disubscribe.

MQTT berguna ketika nilai relay perlu masuk ke dashboard, middleware, historian, atau workflow data melalui broker, bukan hanya dipolling oleh HMI.

Makna MQTT dalam workflow ARServer

MQTT memakai model publish/subscribe. ARServer publish nilai terpilih ke topic, lalu consumer subscribe topic tersebut. Broker menjadi pusat komunikasi antara gateway dan aplikasi pemakai data.

Istilah inti

  • Broker: server MQTT yang menerima dan meneruskan pesan.
  • Topic: nama hierarkis seperti arserver/IED/tag/state.
  • Payload: isi pesan, sering berupa JSON.
  • Subscriber: dashboard, historian, middleware, atau script yang memakai data.

Kenapa topic design penting

Nama topic yang buruk membuat data sulit dicari dan sulit dirawat. Skema topic harus menunjukkan gateway, IED, signal, dan state tanpa memaksa semua consumer memahami object IEC 61850.

Jangan publish value buta: sertakan quality, timestamp, dan status komunikasi agar dashboard tidak menampilkan data stale seolah-olah live.
