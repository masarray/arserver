Workflow bridge

Topic design harus membawa konteks, bukan hanya value

Nilai IEC 61850 biasanya punya konteks: quality, timestamp, object path, dan status komunikasi. Consumer MQTT membutuhkan konteks ini agar dashboard tidak menampilkan data stale atau invalid seolah-olah live.

Alur publish yang disarankan

  1. Pilih point relay penting di ARServer.
  2. Validasi bahwa point tersebut terbaca.
  3. Tentukan skema topic yang menunjukkan gateway, IED, point, dan state.
  4. Publish payload berisi value, quality, timestamp, dan local update time.
  5. Uji broker dan subscriber sebelum dashboard dipakai sebagai acuan.

Contoh topic

Skema topic dapat dibuat konsisten seperti arserver/{ied}/{tag}/state. Payload sebaiknya tetap mudah dibaca untuk debugging dan konsisten untuk aplikasi.

Aturan engineering: publish quality dan timestamp bersama value. Value telanjang tidak cukup untuk judgement operasional.
