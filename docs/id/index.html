Pusat belajar

Tempat mulai yang praktis untuk memahami IEC 61850, Modbus TCP, dan MQTT.

ARServer tidak hanya diposisikan sebagai aplikasi, tetapi juga sebagai peta belajar agar hubungan antarprotokol jelas sebelum user mulai mapping data relay sungguhan.

Protokol 01

IEC 61850 dan MMS

Pahami IED, logical node, data object, data attribute, function constraint, file SCL, dan kenapa MMS umumnya memakai TCP port 102.

Protokol 02

Modbus TCP untuk HMI/SCADA

Pahami kenapa DCS, HMI, dan SCADA sering membutuhkan register map yang stabil, alamat jelas, dan status point yang mudah dipolling.

Protokol 03

MQTT untuk dashboard/data platform

Pahami topic naming, payload JSON, quality, timestamp, broker, dan cara data relay dibawa ke dashboard atau middleware.

Arsitektur

Data relay dibaca sekali, lalu dibagikan ke sistem yang membutuhkan.

ARServer berada di antara relay/IED IEC 61850 dan sistem pemakai data. Jalur baca relay dijaga tetap terkendali, lalu nilai yang sudah dipilih diexpose ke sistem klasik melalui Modbus TCP dan workflow data modern melalui MQTT.

  • Relay / IED tetap menjadi sumber data utama melalui IEC 61850 MMS.
  • ARServer memvalidasi nilai terpilih sebelum output dipublish.
  • DCS, HMI, dan SCADA dapat polling Modbus TCP server.
  • Dashboard IoT, middleware, atau historian dapat subscribe melalui MQTT.

FAQ

Pertanyaan umum sebelum mencoba ARServer.

ARServer itu apa dalam bahasa sederhana?

ARServer adalah gateway Windows yang membaca nilai terpilih dari relay/IED IEC 61850 lalu menerbitkannya sebagai register Modbus TCP dan topic MQTT untuk HMI, SCADA, DCS, dashboard, atau test tool.

Apakah ARServer alat test relay?

Bukan. ARServer bukan relay test set untuk injeksi. Fokusnya adalah membaca data, mapping, publishing, validasi, dan membantu integrasi engineering.

Apakah bisa konek ke relay/IED sungguhan?

Ya, jika relay, network, dan service IEC 61850 yang didukung memungkinkan komunikasi MMS melalui TCP port 102. Selalu uji dulu di bench atau jaringan FAT yang aman.

Apakah perlu MQTT broker?

Perlu jika output MQTT digunakan. Output Modbus TCP tidak membutuhkan MQTT broker.

Kenapa quality dan timestamp penting?

Nilai Boolean tanpa quality dan timestamp bisa menyesatkan operator. ARServer menjaga konteks value agar user tahu data masih fresh, stale, good, atau invalid.

Mulai kecil, validasi jelas

Buat satu mapping IEC 61850 ke Modbus/MQTT yang bersih, lalu kembangkan dengan percaya diri.
