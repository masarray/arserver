Use case MQTT dashboard

Publish nilai relay terpilih ke dashboard dengan konteks yang jelas.

ARServer dapat publish nilai IEC 61850 terpilih ke MQTT agar dashboard, middleware, dan historian bisa subscribe tanpa perlu berbicara IEC 61850 langsung.

Route publish / subscribe

Relay / IED → ARServer → MQTT Broker → Dashboard

Output MQTT berguna ketika sistem pemakai bukan HMI polling tradisional. Broker memungkinkan dashboard, middleware, historian, dan script subscribe ke topic state terpilih.

Payload MQTT yang baik membawa konteks

  • Current value.
  • IEC 61850 source object atau tag name.
  • Quality dan communication state.
  • Device timestamp dan local update time.
  • Status yang jelas untuk stale atau invalid value.

Topic design

Gunakan nama topic yang konsisten, misalnya arserver/{ied}/{tag}/state. Hindari topic yang menyembunyikan identitas IED atau membuat dashboard bergantung pada naming yang tidak terdokumentasi.

Aturan dashboard: jangan tampilkan value tanpa quality dan timestamp. Data relay yang stale bisa tampak normal jika dashboard tidak menunjukkan state dengan jelas.

Kapan use case ini tepat

  • Dashboard engineering membutuhkan nilai relay live.
  • Middleware membutuhkan point SCADA terpilih sebagai pesan JSON-like.
  • Historian atau eksperimen data membutuhkan route broker.
  • Modbus polling bukan model integrasi utama.
