Where ARServer fits best

ARServer is not positioned as a full protection test set. It is a gateway and engineering workspace for reading selected IEC 61850 MMS values, validating them, and publishing them to practical consuming systems.

Best first use case: start with one relay or simulator, select a small number of high-value points, validate source values, then expose them to one Modbus client or one MQTT broker.
HMI/SCADA integrationBridge selected IEC 61850 IED values into stable Modbus TCP registers for HMI, SCADA, or DCS clients.FAT/SAT relay benchUse ARServer as an engineering visibility layer during lab, FAT, SAT, and point-to-point validation.MQTT dashboardPublish selected relay values with quality and timestamp context to dashboards, middleware, or historians.Start from zeroFollow the practical route from network preparation to a running gateway.

How to decide

  • Use HMI/SCADA when the consuming system expects Modbus TCP.
  • Use FAT/SAT when you need evidence, validation, and visible runtime behavior during tests.
  • Use MQTT Dashboard when the consuming system is a broker-based data platform.
